Библиотека для разработки игр в жанре Платформер
================================================

Работа с состяниями объектов
----------------------------

Каждый тип объекта имеет собственный набор состояний. Каждое состояние связано с анимацией и функцией (ее может не быть, то есть равна NULL), которая выполняется в каждом кадре.
Например, для игрового персонажа можно задать состояния: идти влево, идти вправо, прыжок.
::

   register_state(PLAYER_LEFT, player_left_anim, player_left_func, NULL);
   register_state(PLAYER_RIGHT, player_right_anim, player_right_func, NULL);
   register_state(PLAYER_JUMP, player_jump_anim, player_jump_func, NULL);

Первый параметр - это id состояния. Оно должно быть уникально, то есть разное для всех типов объектов.

Второй параметр - анимация, тип animation_t *;

Третий параметр - функция, которая принимает параметр - объект, у которого установлено это состяние. Она запускается один раз при переходе в данное состояние.

Четвертый параметр - функция, принимает параметр - объект, у которого установлено это состяние. Она запускается каждый кадр.

В разных случаях необходимо использовать разные функции. Однократно выполняемые действия при переходе в состояние это: проигрывание звука, задание скорости или ускорения.
Многократные действия - это когда ИИ врагов определяет когда нужно переключиться в другое состояние, выполняет тесты окружения.

Например:
::

   // obj - это сам player
   void player_left_func(object_t *obj)
   {
      set_velocity(obj, make_vec3(-SPEED, 0, 0)); // устанавливает скорость объекту
   }

Аналогичным образом можно настроить поведение и для всех других объектов.

Начальное состояние объекта задается при создании объекта.

Далее в любой момент можно сменить состяние:
::

   object_set_state(player, get_state(PLAYER_JUMP));

Первый параметр - object_t *, объект которому меняем состояние.

Второй параметр - state_t, состояние, которое можно получить с помощью функции state_t get_state(int id).

Реализация состояний объектов
-----------------------------

Для простоты удобно хранить все состояния в одном массиве информации о состояниях, где id состояния - это индекс в массиве. Тогда получается достаточно просто регистрировать состояния и получать их.
Массив имеет фиксированную длину MAX_STATE_ID.

Однократная функция запускается при установке состяния (object_set_state). Многократная запускается в objects_update.

Связь состояний и графики
-------------------------

При создании объекта, создается анимация (add_animation), которая сохраняется в сам объект. Координаты берутся из объекта.

При изменении состояния (object_set_state), предыдущая анимация удаляется (remove_sprite), и добавляется новая.


Настройка взаимодействия объектов
---------------------------------

Библиотека автоматически обрабатывает столкновения объектов. Но пользователь может указать как игра должна реагировать на то или иное взаимодействие объектов разных типов.
::

   void set_reaction(int obj_type1, int obj_type2, void (*react_func)(object_t *o1, object_t *o2));

Регистрирует, что при взаимодействии объекта с типом obj_type1 и объекта с типом obj_type2 будет вызвана функция, куда будут переданы два взаимодействующих объекта.

Скроллинг графики
-----------------

Виды скролинга: горизонтальный, вертикальный, смешанный.

Скроллинг задается между двумя экранами. Первый экран задается через set_screen, а другие через set_screen1, set_screen2, set_screen3.
Изначально все экраны пустые (NULL).

::

   ==========================
   |   screen  |  screen1   |
   ==========================
   |  screen2  |  screen3   |
   ==========================

Окно смещения задается через функцию:
::

   void set_scroll(int ofs_x, int ofs_y);

Смещение задается в пикселях относительно левого верхнего угла экрана screen. Это смещение не влияет на спрайты, только на сетку.

Чтобы делать плавное движение окна, нужно каждый кадр менять смещение.
